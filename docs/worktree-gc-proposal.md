# Proposal: safe fleet worktree GC

Status: design only. No collector, quarantine operation, or deletion is implemented here. The `worktrees 695 > 40` warning is a count signal, not evidence that any particular directory is safe to remove. This proposal covers job worktrees directly under `~/Projects/ashlrai/wt/`; it does not authorize changes to other worktree pools.

## Current boundaries

Stack's `packages/cli/src/commands/fleet-bets.ts` derives outcomes from fleet events and `scripts/fleet-metrics.ts` counts finish/reap and publish events. As documented in [fleet-metrics.md](fleet-metrics.md), those are event counts, not a complete authoritative inventory or proof of a particular worktree's safety. A finish, reap, publish event, or PR URL alone is insufficient.

The local Phantom checkout has a separate reaper in `src/core/inbox/temp-worktree-reaper.ts` for named throwaway worktrees under `~/.ashlr/tmp`, using owner PID/start identity and repo leases; it can force-remove its scoped scratch worktrees. Its markerless age fallback and force removal must not be generalized to job worktrees. The historical `workplans/2026-09-02-unified-agent-operating-system/reclaim_hub_worktrees.mjs` is a mutating, separately scoped recovery script; it is not a safe collector for this pool. The dispatcher's creation, keep, publish and reap implementation and authoritative job-to-path/marker contract were not established in this Stack checkout. Before implementation, locate and audit the deployed dispatcher and its locks and marker producers; do not infer their behavior from filenames or logs.

## Classification, in precedence order

Each entry gets one primary class and all applicable reasons. Unknown, stale, contradictory, inaccessible or incomplete evidence always blocks removal. A successful command with empty output is distinct from a failed command.

1. **Preserve** if the directory is a canonical checkout, outside the exact configured root, a symlink or otherwise untrusted path; is locked; has `.publish` or `.kept` (including unreadable or non-regular markers); is dirty; has unpushed commits; or has a running, queued, launching, or otherwise not provably terminal job. Check markers at the worktree root and any additional locations established by the dispatcher contract. A marker's presence blocks removal regardless of its contents or age. Inspect tracked, staged, untracked and ignored files and submodules; errors or uncertainty preserve. Ignored files may contain the only copy of work.
2. **Quarantine candidate** if its `.git` pointer is missing, malformed, points to missing or inconsistent administration data, or cannot be reconciled with the owning repository's registration. This is a report label only: preserve it in place until an independently designed recovery procedure can prove it is inactive and preserve all bytes, metadata and Git objects. A broken pointer does not prove the tree is disposable. Marker, dirty and activity protections still apply; do not move a running or uncertain tree.
3. **Removable candidate** only when all of the following are positively established for the exact repository, job and HEAD: a terminal job with no active owner; a clean tree including ignored files and submodules; no markers or lock; a valid linked-worktree registration; and both publication and merge evidence. Publication must identify the exact job/repository and commit on a durable remote ref, confirmed against the intended remote, not merely a local remote-tracking ref. Merge evidence must establish that exact commit is reachable from the current authoritative remote default branch. Squash/rebase merges do not prove reachability of the original commit: preserve unless a separately verified mapping and durable remote ref also protect every local commit. Detached HEAD, missing upstream, deleted remote branch, unavailable remote, shallow/incomplete history or ambiguous identity is preserved unless equivalent exact evidence is independently established. Do not delete local branches or refs as part of worktree GC.
4. **Preserve/unknown** for everything else, including unmerged, unpublished, missing job evidence and Git or network errors. Age and directory size never confer eligibility.

To detect unpushed work, require every commit reachable from the worktree HEAD and any worktree-specific refs to be reachable from a verified durable remote ref. Include detached HEAD and commits made after publication. If the full ref set or remote state cannot be established, preserve. A branch being merged is not by itself proof that all worktree commits were pushed.

## Proposed dry run

Inventory direct children without following symlinks and reconcile them against `git worktree list --porcelain -z` for each known owning repository, including registered-but-missing paths. Resolve the root and repository identities safely; do not trust an arbitrary `.git` pointer as permission to inspect or operate outside known repositories. Never run prune, fetch, checkout, hooks, or any mutating Git command. Query authoritative remote state read-only; do not rely on cached refs as current. Disable hooks and optional Git facilities that execute external commands, bound execution time and output, and avoid emitting file contents, remote credentials or raw command errors.

Produce versioned JSON and a human summary with scan time, root, completeness/errors, counts by class and reason, and per-entry path, repo identity, HEAD, job identity/state, marker and cleanliness results, publication/merge evidence and observation times. Record missing evidence explicitly; distinguish inaccessible from absent. Paths and job identifiers may be sensitive: keep output local and restrict its permissions if saved. An incomplete scan must say so and must not present a removal total as actionable. No dry-run output is an authorization token.

## Future execution design

Implement separately in the dispatcher owner, after identifying a shared lock or lease covering job creation, reuse, marker writes and cleanup. Under that lock, re-read every predicate immediately before each operation, bind the decision to path/inode, repository, registration and exact HEAD, and abandon on any change or uncertainty. A check followed by an unlocked delete is unsafe. Protect against symlink substitution and path traversal; never operate on the root itself or another repository. Use Git's non-force worktree removal only for a freshly verified registered candidate; do not recursively delete or globally prune. Recheck remote and job authority and markers under the relevant coordination protocol, not merely a stale dry-run report. If the dispatcher cannot provide this coordination, retain report-only mode.

Quarantine requires a separate design for atomic same-filesystem movement, registration repair, recovery manifests and crash recovery; moving a linked worktree can invalidate its `.git` relationship. Until then, quarantine means classification and preservation in place. Never remove `.publish` or `.kept` to make an entry eligible. Failures stop the affected operation and remain visible; collect metrics for preserved, unknown, candidate and failed entries without logging secrets.

Before enabling any executor, test with isolated temporary repositories and fake job/remote authorities: clean merged and published, unpushed or detached commits, squash merge, dirty and ignored files, submodules, both markers, locked trees, orphan pointers, missing registrations, active and reused PID identities, unavailable or stale authority, symlinks and paths with whitespace, concurrent marker/job/HEAD changes, interrupted operations, and repeated runs. Assert that no protected fixture is moved, removed or pruned. Roll out reporting first and compare classifications with dispatcher records; the count threshold alone must never trigger deletion.
