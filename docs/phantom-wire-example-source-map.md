# Phantom wire example source map

The webhook example that wiring drops into a project is generated at run time —
there is no checked-in example file to link to. For each recipe provider in
[`WEBHOOK_PROVIDERS`](../packages/core/src/ai/phantom-wire.ts#L46) (`stripe`,
`clerk`, `supabase`, `github`),
[`writeWebhookStub`](../packages/core/src/ai/phantom-wire.ts#L110) writes
`.stack/webhooks/<provider>.ts` under the working directory — creating
`.stack/webhooks/` as needed and overwriting any existing file — with the text
built by [`webhookStubFor`](../packages/core/src/ai/phantom-wire.ts#L117).
Stubs are plain files, so they are still written when Phantom itself is
missing. This map points at the template lines in
[`phantom-wire.ts`](../packages/core/src/ai/phantom-wire.ts) that produce each
part of the generated example.

## The generated example

| Part of `.stack/webhooks/<provider>.ts` | Source | What it becomes in the file |
| --- | --- | --- |
| File header | [preamble template](../packages/core/src/ai/phantom-wire.ts#L118) | `` // Auto-generated by `stack apply` — webhook handler stub for <provider>. ``, then warnings that the example is commented out, does not verify signatures, and must not be deployed as-is. |
| Secret guidance | [secret comment](../packages/core/src/ai/phantom-wire.ts#L124) | A commented `phantom reveal` line naming the secret chosen by [`webhookSecretKeyFor`](../packages/core/src/ai/phantom-wire.ts#L167) (for example `STRIPE_WEBHOOK_SECRET`). Generating the file runs nothing and retrieves no value. |
| Handler skeleton | [handler template](../packages/core/src/ai/phantom-wire.ts#L127) | `handle<Provider>Webhook` — the provider name with its first letter uppercased by [`capitalize`](../packages/core/src/ai/phantom-wire.ts#L197) — reads the header named by [`signatureHeaderFor`](../packages/core/src/ai/phantom-wire.ts#L182), returns 400 when that header is missing or empty, reads the body, and returns 200. Every line stays `//`-commented in the file. |
| Verification reminder | [TODO template](../packages/core/src/ai/phantom-wire.ts#L131) | The `TODO(security)` block mapped below — the stub's reminder that signature verification is not implemented. |
| Success response | [return template](../packages/core/src/ai/phantom-wire.ts#L141) | `return new Response("ok", { status: 200 })`, which any non-empty signature header reaches if the example is uncommented without implementing verification. |

## The verification reminder

The reminder is the `TODO(security)` block emitted between the body read and
the success response. As generated for a Stripe recipe entry, it reads:

```ts
//   // TODO(security): signature verification is NOT implemented here. The
//   // header check above proves only that a signature header arrived; its
//   // value is never compared to anything. Until this TODO is done, `body`
//   // is unauthenticated, attacker-controlled input — anyone who can POST
//   // to this endpoint can forge a stripe webhook.
//   // Stripe: `stripe.webhooks.constructEvent` — HMAC-SHA256 with timestamp tolerance.
//   // Verify over the exact raw body bytes with the webhook secret
//   // (`phantom reveal STRIPE_WEBHOOK_SECRET`) and compare in
//   // constant time; reject missing or invalid signatures, and only then
//   // parse, trust, or act on the body.
```

It has two halves in the [template](../packages/core/src/ai/phantom-wire.ts#L131):

- **The warning** — a present signature header authenticates nothing, so the
  body remains unauthenticated, attacker-controlled input until verification
  exists.
- **The pointer** — the provider-specific hint interpolated at
  [line 136](../packages/core/src/ai/phantom-wire.ts#L136) by
  [`verificationHintFor`](../packages/core/src/ai/phantom-wire.ts#L152), then the
  [closing instructions](../packages/core/src/ai/phantom-wire.ts#L137) to verify
  the exact raw body bytes with the webhook secret, compare in constant time,
  and reject missing or invalid signatures before parsing, trusting, or acting
  on the body.

The reminder stays a comment even if the surrounding handler is uncommented;
implementing it means adding the provider's current verification scheme before
deploying, not uncommenting anything.

## Verify the map

Locate the template and the reminder in the source:

```sh
grep -n 'writeWebhookStub\|webhookStubFor\|TODO(security)' packages/core/src/ai/phantom-wire.ts
```

Expect `writeWebhookStub` near line 110, `webhookStubFor` near line 117, and the
`TODO(security)` line near line 131. The pinned check regenerates a real stub
and confirms the map and excerpt still match:

```sh
HOME=$(mktemp -d) bun test scripts/phantom-wire-example-source-map.test.ts
```
